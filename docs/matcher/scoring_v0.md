# マッチャー スコアリングロジック v0.1

> 策定者: [[ceo|CEO エージェント]]
> 目的: 12問の回答から軸プロファイル（6軸 × −2〜+2）を算出する
> 関連: [[axes_v0]] | [[questions_v0]] | [[recommendation_v0]]

## 全体フロー

```
[親の回答 12問 + 文脈3問]
        ↓
[各質問を −2〜+2 にマップ]
        ↓
[軸ごとに2問の平均を取る]
        ↓
[6軸スコア（−2.0〜+2.0）が出る]
        ↓
[極性ラベル + 不確実性フラグを付与]
        ↓
[recommendation_v0 の推奨ロジックへ渡す]
```

## ステップ 1: 回答 → スコア変換

### 5段階リッカートのスコア化

| 回答 | スコア |
|---|---|
| 強く A 寄り | −2 |
| ややA | −1 |
| 中立 | 0 |
| ややB | +1 |
| 強く B 寄り | +2 |

### 質問と軸の対応表

| Q | 軸 | A極（−側） | B極（+側） | 寄与 |
|---|---|---|---|---|
| Q1 | R 応答性 | 高応答（R+） | 自律探索（R−） | 反転（A=+2をR=−2、B=+2をR=+2に） |
| Q2 | R 応答性 | 高応答（R+） | 待つ（R−） | 反転 |
| Q3 | S 構造性 | ルーティン（S+） | 流動的（S−） | 反転 |
| Q4 | S 構造性 | 予定優先（S+） | 流動（S−） | 反転 |
| Q5 | I 主導権 | 親主導（I+） | 子主導（I−） | 反転 |
| Q6 | I 主導権 | 親主導（I+） | 子主導（I−） | 反転 |
| Q7 | E 評価観 | 結果賞賛（E+） | 過程賞賛（E−） | 反転 |
| Q8 | E 評価観 | 能力肯定（E+） | 過程問い（E−） | 反転 |
| Q9 | P 早期化 | 先取り（P+） | ゆっくり（P−） | 反転 |
| Q10 | P 早期化 | 早期投資（P+） | 焦らない（P−） | 反転 |
| Q11 | C 関係性 | つながり（C+） | 個別自立（C−） | 反転 |
| Q12 | C 関係性 | 甘え肯定（C+） | 自立促進（C−） | 反転 |

**注**: questions_v0.md ではA選択肢が「+側（応答性高い・構造的・親主導…）」になるよう統一しているので、 **Aを選んだほど +側** にスコアが寄るよう **回答スコアを反転する**:

```
raw_score = (回答が「A寄り」=2, 「ややA」=1, 「中立」=0, 「ややB」=−1, 「B寄り」=−2)
```

つまり A=+2、B=−2 の配点で集計する（実装側では好きな向きで構わない、ロジックを一貫させる）。

## ステップ 2: 軸スコアの算出

各軸につき2問のスコアを **単純平均** する。

```python
R = (Q1 + Q2) / 2
S = (Q3 + Q4) / 2
I = (Q5 + Q6) / 2
E = (Q7 + Q8) / 2
P = (Q9 + Q10) / 2
C = (Q11 + Q12) / 2
```

結果は **−2.0 〜 +2.0** の連続値。

### 軸プロファイル例

```
親A の軸プロファイル:
  R = +1.5（応答性高め）
  S =  0.0（中立）
  I = −1.5（子主導寄り）
  E = −1.0（過程評価寄り）
  P = −0.5（ややゆっくり寄り）
  C = +1.5（関係性重視）
```

## ステップ 3: 極性ラベル化

連続値を分かりやすい言葉に変換する（結果画面用）。

| スコア範囲 | ラベル | 強度 |
|---|---|---|
| +1.5 〜 +2.0 | 強くA極寄り | 強 |
| +0.5 〜 +1.4 | ややA極寄り | 中 |
| −0.4 〜 +0.4 | バランス型 | 中央 |
| −1.4 〜 −0.5 | ややB極寄り | 中 |
| −2.0 〜 −1.5 | 強くB極寄り | 強 |

### 軸ごとのラベル例

| 軸 | +側ラベル | 中央ラベル | −側ラベル |
|---|---|---|---|
| R 応答性 | 察し型 | 状況応答型 | 観察・見守り型 |
| S 構造性 | リズム重視型 | 柔軟型 | 流れ尊重型 |
| I 主導権 | 誘導・伴走型 | バランス型 | 子主導・委ね型 |
| E 評価観 | 結果共有型 | 状況応答型 | 過程対話型 |
| P 早期化 | 早めの環境づくり型 | 中庸型 | 発達待ち型 |
| C 関係性 | つながり重視型 | 個と関係の両立型 | 個別自立尊重型 |

**注**: 「タイプ」を「型」と表現するのは、MBTIのような固定的タイプ感を回避するため。 **「現時点の傾向」** であることを言葉から伝える。

## ステップ 4: 不確実性フラグ

以下のいずれかが該当する軸は **「結果に幅がある」フラグ** を付け、結果画面で「この軸はあなた自身でも揺れているかもしれません」と注記する。

### 不確実性フラグの条件

1. **2問の回答が乖離（差が3以上）**: 例えば Q1=+2 で Q2=−1 → 平均 +0.5 だが内訳が割れている
2. **両問が中立（0）**: 強い傾向がなく、軸として情報量が薄い
3. **文脈質問CQ3（モヤモヤ）と矛盾**: 例えば軸プロファイルは S+ なのに「生活リズム・寝かしつけ」が悩み → S+ の理想と現実のギャップを示唆

### フラグ付き軸の扱い
- 推奨理論の重み付けで **その軸の影響度を 50% に減衰**
- 結果画面で「この軸はゆらぎがあります。理論Aと理論Bの間で、家庭の様子に応じて使い分けるのが良さそうです」と提示

## バリデーション・キャリブレーション

### Phase B 検証で確認すべきこと

1. **軸スコア分布**: 100ペルソナで軸スコアが正規分布に近いか（全員が中央に寄ったら質問が悪い）
2. **軸間の相関**: 設計時の相関仮説（axes_v0.md の独立性表）と実測が合うか
3. **テスト-再テスト信頼性**: 同じ親が2週間後に回答して、軸スコアの相関 r > 0.7 が出るか
4. **専門家判定との一致**: 育児支援者・心理士が「この親にはこの理論」と判定したものと、マッチャー推奨の重なり率

### キャリブレーション方法（Phase B 終了後）

- 軸間の相関が強すぎる場合 → 質問差し替え or 軸統合
- 特定の軸でスコアが極端に偏る場合 → 質問の難易度・社会的望ましさバイアスを再調整
- 推奨理論との対応で「絶対に出ない理論」「常に出る理論」がある場合 → 推奨ロジックの重み再調整

## 注意事項（実装者向け）

1. **回答漏れ対応**: 1問でも未回答なら軸スコアを算出しない（中立で埋めない）
2. **タイプ感の言葉を避ける**: 「あなたは○○型です」ではなく **「あなたの傾向は○○寄りです」**
3. **数値の生表示を避ける**: 「R=+1.5」のような生スコアはユーザーに見せない。ラベルと「弱・中・強」で表現
4. **再診断推奨**: 「3-6ヶ月後にもう一度試してみてください。子の年齢・あなたの状況で結果は変わります」を明示
5. **データ保存と削除**: 軸プロファイルは将来の再診断比較のために保存可。ユーザーの削除リクエストは即時対応

---

## 保留事項

1. **重み付けの導入**: 全質問均等重みでよいか、それとも質問ごとに重み（例: Q11 関係性は信念質問なので重み低、Q5 主導権は行動質問なので重み高）を持たせるか
2. **時系列スコア**: 同じ親が複数回診断した時の **変化追跡**（成長・状況変化）を可視化するか
3. **両親別スコア**: 父・母で別に診断して **2人の軸プロファイル比較** を見せる機能を Phase 3 で検討
4. **「今日の調子」補正**: 親の睡眠不足・気分で回答が揺れる。診断前に「いまの体調」をミニチェックして補正するか
