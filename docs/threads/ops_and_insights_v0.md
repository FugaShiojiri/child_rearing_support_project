## 1. 大前提（揺らさない事実）

- **現状フォロワー≒0・投稿viewsもほぼ0**。これは想定内＝既知の真因「リーチ供給不足」（[[project-distribution-reality]]）。
- したがって**初期の指標0で揺れない**（[[feedback-no-panic-at-zero]]）。テーマ選定などの判断は**リーチが付いてから**。総views<50は「判定時期尚早」と機械的に扱う。
- 守る一線（不可侵）：①全部無料（連載・物語は課金しない）②量産でもトーンを1本も崩さない（オーナー目視＝承認ゲート）③誠実性ガードレール（実話詐称なし・親バッシングなし・非権威）④燃え尽き監視。
- トーンは普段の話し言葉・気取り/詩的モチーフ禁止（[[feedback-writing-tone]]）。

## 2. コンテンツの二本立て（役割分担）

| 型 | 狙い（KPI） | 文体 | 終わり方 | 例 |
|---|---|---|---|---|
| **痛みテーマ型**（問いかけ） | リーチ＋**能動的反応**（返信/リポスト/引用）を取る。有料記事テーマ選定の実験台 | 本音・共感、1つの悩みに絞る | **問いで締める**（返信を促す） | 赤ちゃん返り/夜泣き/イヤイヤ期/叱り方（test①〜④） |
| **物語型**（情景） | 保存・静かな共感・**プロフィール→note回遊** | 情景描写、理論名を出さない | 静かな余韻（問いにしない） | 物語①靴下/物語②比べてしまう |

- 役割を分けるのが肝。**返信を取りに行くのは痛みテーマ型、回遊を取りに行くのは物語型**。物語型の返信が0でも失敗ではない（KPIが違う）。

## 3. 投稿リズム（cadence）

- **痛みテーマ：隔日**（現行 6/15・6/17・6/19・6/22 の4本テスト）。
- **物語：週1**（T097供給ライン。物語①6/10→物語②6/14→以降週1で新作1本）。
- **一括放出しない／露出は分散**（phase2決裁準拠）。1日複数本の連投はしない。
- オーナーが手を動かす作業（承認）は**19:00–22:00の家族時間を避けて**依頼（[[user-availability-family-time]]）。投稿実行自体は非同期で時間帯自由。
- 燃え尽き歯止め：制作はCEO（Claude）が背負う。3本連続でトーン劣化が出たら該当型を減速。

## 4. 成功指標とインサイト運用ループ

**主指標 = 能動的反応（replies + reposts + quotes）**。スキ/いいねは「問い/相談の質」を持たないため主指標にしない（[[project-insight-collection]]／T100準拠）。
**副指標 = views（リーチ）／プロフィール表示（note回遊の入口）／followers_count（蓄積）**。

ループ：
1. **投稿**（承認済みドラフト → `/post-threads` か `python3 scripts/post_threads.py --date YYYY-MM-DD --commit`）。
2. **測定**（`python3 scripts/threads_insights.py`）。テーマ別に views/返信/RP/引用/能動計を一覧。
3. **判定**（CEO）：
   - 痛みテーマ4本が出揃い、かつ**リーチが立ってから**、能動的反応トップのテーマを特定。
   - そのテーマが現在の有料記事 paid01（赤ちゃん返り/甘え）と異なれば、**T050のテーマ寄せ替え**をCEO決裁。一致すれば確定。
4. **報告**：オーナーへ数字つきで簡潔に（推測でなく実数）。

> 注意：投稿単位 views はMeta側が「開発中」指標で反映が遅い。アカウント単位のプロフィール表示/フォロワー数と併読して傾向を見る。

## 5. note への導線（T101の実体・Threads版）

- Threadsは外部リンクのクリック導線が弱いため、**本文にURLを貼らない**（プロフィールのリンク=note に集約）。
- 物語型で世界観を出し、**「続きや関連の声かけはプロフィールのnoteに」と本文外の文脈**で回遊を促す（押し付けない）。
- 痛みテーマ型は問いで会話を起こし、返信のやりとりの中で自然にnoteの該当記事に触れる（過度な宣伝はしない）。
- フォロワー増を待たず、非フォロワーのプロフィール流入（現在170/直近）を回遊につなげるのが当面の経路。
